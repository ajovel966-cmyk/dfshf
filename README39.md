# 装了广告拦截后Telegram网页版一直白屏：6种白屏形态对照表 + 12个扩展4轮定位的二分法

装了广告拦截插件后，网页版一直是白屏——地址栏转两下，标签页标题出来了，页面却干干净净一片白，连一个按钮、一个字符都不给我。刷新十几次、重启浏览器、换网络，全是白屏；清缓存没用，退出重登也没用，连"重新登录"的界面都加载不出来。

等我按 F12 打开控制台，第一行报错就把答案交出来了：

```
GET https://.../app.js net::ERR_BLOCKED_BY_CLIENT
```

`ERR_BLOCKED_BY_CLIENT` 这个词组里的 "CLIENT" 指的就是浏览器本地那一侧——**请求根本没出门，是被你自己装的扩展在半路掐掉的**。页面缺了关键的脚本文件，框架起不来，剩下的就只有那片白。

这条报错比任何教程都值钱：它把"网站坏了"和"我这台机器坏了"一次性分开了。下面是十几台不同配置的电脑上压出来的对照表和定位顺序，按"关掉的风险从小往大"排，扩展清单可以直接照抄。相关的登录检查清单与浏览器设置说明，在 [Telegram网页版中文指南](https://tlgroc-web.com) 上能对着图核对。

## 白屏不是"加载慢"，是渲染在第一帧就被打断了

这个概念不拧正，排查方向一定跑偏。

网页版是单页应用：外壳先加载，再由几个脚本文件把界面"画"出来。广告拦截类扩展的工作方式是维护一张规则表，把匹配规则的请求挡在本地，连服务器都不问。规则按域名和路径片段写，**误伤单页应用的概率并不低**——尤其是接口和静态资源放在同一个域名下的站点。

故障链条因此是这样：规则命中 → 主脚本被拦 → 框架没初始化 → DOM 里只剩一个空的挂载节点 → 白屏，而页面状态码可能还是 200。

三个反直觉的现象也就解释得通了：

- 换 Edge、换手机一切正常，因为规则表不在那台浏览器里；
- 清缓存越清越乱，被拦的不是缓存，是每一次的新请求；
- 页面不是"打不开"，是**打开了但没内容**——有标题有图标，就是不给你界面。

## 六种白屏长什么样：先认形态，再动手

六种形态的处理思路完全不同，对着表看一眼，能省掉一半瞎试。

| 白屏形态 | 你眼睛看到的 | 控制台 / 网络面板的线索 | 高发嫌疑 |
| --- | --- | --- | --- |
| 纯白无物 | 整页全白，标题正常，右键能弹菜单 | `net::ERR_BLOCKED_BY_CLIENT` 连续多条 | 广告拦截、隐私防护 |
| 只剩外框 | 顶部有一条灰边或一个转圈，中间空 | 主脚本 200 但关键 chunk 404/被拦 | 脚本管理类、拦截类 |
| 一闪即白 | 界面出现过零点几秒，随即被抹平 | 报错里出现 `removeChild` 或 `null` 读取 | 翻译类、划词类 |
| 局部空白 | 聊天列表有，右侧一片白 | 单个接口请求被拦，其余正常 | 拦截规则误伤接口路径 |
| 二维码区空 | 登录页正常，扫码框是空白方块 | 图片域名请求被拦 | 图片类拦截规则 |
| 白屏加提示 | 白屏上盖一句"页面已被阻止"或错误页 | 扩展自带的拦截落地页 | 强拦截模式、企业管控 |

第六种最好认，也最容易被误读成"站点被封"。真被封是浏览器层面的连接失败，不会带着某个扩展的品牌名。

## 为什么无痕窗口有可能骗了你

很多教程第一步就让你开无痕（`Ctrl + Shift + N`）。这个动作有价值，但它有个前提常被忽略：**扩展默认不在无痕里运行**。

扩展的"在无痕模式下允许"没勾时，无痕窗口天然干净——在里面看见正常，只能证明问题不在网站、不在网络，证明不了是哪个扩展；反过来，勾了允许无痕的扩展照样白屏，就会被误判成"不是扩展的问题"，一头扎进清缓存里出不来。

更可靠的对照是**新建一个浏览器配置文件**，用它当"无菌室"：

1. 地址栏输入 `chrome://settings/manageProfile`（旧版是 `chrome://settings/people`）。
2. 点"添加"，起个名字比如 `clean-test`，勾选"创建桌面快捷方式"。
3. 在这个新配置文件里打开同一个地址，不要登录任何扩展商店账号。

新配置文件里一切正常，而你的日常配置文件白屏——结论就定死了：**问题在你那份扩展配置里**。这一步不破坏任何登录状态，比清缓存安全得多。

## 12个扩展怎么在4轮内揪出来

假设你的 `chrome://extensions` 里有十二个扩展在跑。一个个关、一个个试，最坏情况要试十二次；用二分法，四轮之内必然收敛。

1. **先记一份清单**。打开 `chrome://extensions`，把"已开启"的那几个截图留存，顺手确认右上角"开发者模式"的状态。
2. **掐掉一半**。把第 1 到第 6 个扩展的开关关掉，剩下一半保持开启，回网页版按 `Ctrl + Shift + R` 强制刷新。
3. **看结果定方向**。白屏消失，说明元凶在被关掉的那一半里；白屏还在，元凶在留着的那一半里，把已关的六个重新打开、去关另外六个。
4. **重复到只剩一个**。每轮把候选集砍半：6 → 3 → 2 → 1。十二个扩展最多四轮，实际经常两轮就见分晓。

定位到那个扩展后先别卸载。省事的做法是**降权限而不是删扩展**：

进入该扩展的"详情"页，找"网站访问权限"这一项。Chrome 新版给的是三档——"在点击时"、"在特定网站上"、"在所有网站上"。**把它从"在所有网站上"改成"在点击时"**，等于告诉浏览器：这个扩展不许在后台擅自改页面，我点了它才动。绝大多数人改完这一档，白屏就没了，而扩展在别的站点上照常工作。

老版本 Chrome 里这一项叫"在以下网站上读取和更改数据"，位置在详情页往下拉，语义一样。

## 四类最爱打架的扩展，各自的收手方式

真正需要动手的地方不多，四类扩展四种处理法，别用同一招硬套。

**广告拦截类（uBlock Origin、AdGuard）**：点浏览器工具栏上的扩展图标，有一个大的电源开关，点一下就是"对当前站点停用"，刷新即可。想长期共存，就在扩展设置里把域名加进白名单。别图省事直接删——它的规则在别的站点上是有用的。

**翻译类（Google 翻译扩展、各类双语对照扩展）**：这类扩展会遍历并重建页面节点，单页应用里被它改过的节点，框架自己再操作时就会报 `removeChild` 之类的错，表现为"点按钮没反应""输入框打不进字"，甚至界面上半截白。处理方式是进扩展设置，把该域名加进"不翻译的网站"。

**密码管理器（LastPass、1Password、Bitwarden）**：最容易被冤枉的一类。它不拦请求，但会在输入框里抢焦点、注入浮层。登录页的二维码容器被浮层压住时，扫码区不刷新、点"确认"没反应。在扩展的"设置 → 自动填充"里关掉"内嵌自动填充"，或对该站点禁用，问题立刻消失。

**企业管控类**：这类扩展显示"由你的组织管理"，开关是灰的、删不掉。先去 `chrome://policy` 看策略来源——这种只能找 IT，自己在浏览器里折腾一晚也关不掉。

## 改完还不白屏，但登录仍然怪：两个连带故障

扩展冲突经常不是一个人作案。白屏解决之后，若是还剩"扫码没反应""一直转圈"，回头看这两处：

- **规则残留**。有些拦截扩展停用后规则仍在内存里，需要把该站点的数据清一次再刷新。走 `F12` → 应用 → 存储 → 清除网站数据，只清这一个站点，别的网站不受影响（图文步骤见 [缓存与 Cookie 清理](https://tlgroc-web.com)）。
- **两个同类扩展同时开着**。两个拦截器、两个翻译器并存，规则互相覆盖，故障极难复现、时好时坏。**同类扩展只留一个**，能省掉大量玄学问题。

## 把扩展管成一支不打架的队伍

我的做法固定下来了：日常配置文件只留五个扩展，拦截类只留一个，翻译类设成手动触发，密码管理器只对需要的站点开内嵌填充；另外留一个干净的 `clean-test` 配置文件，专门验证"到底是网站的问题还是我的问题"。这个习惯比任何排查技巧都省时间。

扩展冲突这事儿的本质，是**两个都写着"为你好"的东西在同一块页面上抢控制权**。搞清楚谁在抢、抢的是哪一步，白屏就不再是玄学。真要按症状逐条对照，[tlgroc-web.com](https://tlgroc-web.com) 上把登录前的浏览器检查、缓存与 Cookie、通知与下载分开写成了几节，碰到具体问题挑一节看，不必从头读到尾。扩展这一层，记住一句话就够：**先认白屏形态，再降扩展权限，能不卸载就别卸载。**
