# 缓存清了三次网页版还在转圈：按三层顺序排查，十分钟找到电报网页版登不上的真卡点

上周三下午，一位做跨境跟单的读者连着给我发了六条消息，配三张截图。三张图是同一个画面：Telegram 网页版左侧会话栏一片灰，中间一个圆环匀速转，二维码区域始终没渲染出来。

她说自己清了三次缓存。第一次只勾「缓存的图片和文件」，页面回来一半，能看见登录框的边框；第二次把「Cookie 及其他网站数据」也勾上，登录框没了，只剩转圈；第三次索性把时间范围改成「时间不限」全清一遍，圈还在转。

我远程看了一眼，问题不在缓存：她电脑上装着一个脚本管理扩展，公司网络又挂着系统代理，扩展把网页版赖以为生的长连接当成可疑脚本拦掉了。清三次缓存，等于在错误的楼层敲了三次门。

清缓存只覆盖"本地静态资源坏了"这一种情况。真正常见的卡点分布在三个位置，而且**有先后顺序**——顺序错了，清得越多，判断越乱。这篇讲的就是这三层怎么排、每层用哪个动作验证、到哪一步必须停下来。

## 转圈、白屏、报错页，是三种不同的病

同样是"打不开"，浏览器给出的信号完全不同，指向的位置也完全不同。

| 你看到的画面 | 大概率卡在哪 | 该做的第一个动作 |
| --- | --- | --- |
| 圆环一直转，没有任何报错，二维码区域空白 | 长连接没建立：扩展拦截、代理回环、DNS | `Ctrl + Shift + N` 开无痕对照 |
| 页面白屏，或只有文字没样式、按钮点不动 | 本地静态资源损坏 | 只清缓存，再 `Ctrl + F5` |
| 整页报错，地址栏下一行小字 `ERR_XXX` | 链路、证书或系统时间 | 先把报错码读出来 |
| 登录框出现了，扫码后停在"等待确认" | 手机端确认、会话数量上限 | 手机端「设置 → 设备」 |
| 登录框闪一下退回扫码页 | Cookie 被拦、站点数据未放行 | 只针对该站点放行数据 |

太多人把第一行当第二行处理——转圈就去清缓存。转圈的典型特征是"没有任何错误码"，说明请求在更早处就被掐断，浏览器连报错的机会都没拿到，这类问题清一百次也不会好。

## 三层排查图：一层不过，别往下一层猜

下面这张表是我现在实际用的顺序。关键是右边那一列：**通过判据是用来"排除"的**，某一层成立就锁定这一层，原地解决。

| 顺序 | 这一层管什么 | 一个验证动作 | 通过判据（成立即锁定本层） |
| --- | --- | --- | --- |
| 第一层 · 浏览器本地状态 | 缓存、Service Worker、扩展、站点权限 | 开一次无痕窗口访问 | 无痕能出二维码、常规窗口不能 |
| 第二层 · 链路与时间 | DNS、系统代理、证书、系统时钟 | 读报错码 + 校时 + 换一条网络 | 出现明确 `ERR_` 报错页 |
| 第三层 · 会话与账号 | 设备上限、两步验证、异常登录限制 | 手机端看活跃会话列表 | 列表里没有这台浏览器 |

三层从"最便宜"排到"最贵"：第一层改几个开关，第二层换个网络，第三层要动账号。反着来——先怀疑账号被限制、再折腾网络、末尾才想起扩展——是最费时间的走法。

## 第一层怎么验：分清"缓存"和"站点数据"

无痕窗口是最好用的对照实验。`Ctrl + Shift + N`（Firefox 是 `Ctrl + Shift + P`）开一个，粘贴同一地址。无痕不带任何扩展、不带旧 Cookie，能打开就说明常规窗口里有东西在捣乱。

1. 地址栏输入 `chrome://extensions`，把「广告拦截」「脚本管理」「网页翻译」「代理/VPN」四类扩展整体关掉再刷新。一次关一组，二分法最快。
2. 只想清这一个站点：点地址栏左侧的锁形图标 →「Cookie 和网站数据」→「管理设备上的网站数据」→ 搜站点名 → 删除。Edge 的路径是「设置 → Cookie 和网站权限 → 所有权限 → 站点数据」。
3. 清 Service Worker 残留。`F12` →「应用（Application）」→ 左侧「Service Workers」→ `Unregister`；再到「存储（Storage）」→「清除网站数据」。较新版本的 Chrome 已把 `chrome://net-internals` 的部分面板移走，走 DevTools 更稳。
4. 检查权限。「设置 → 隐私和安全 → 网站设置 → 摄像头」，确认站点不是「阻止」——扫码要调摄像头，被拦就停在扫码页前面。麦克风、剪贴板同理。

各浏览器这几处菜单的差异，[站上按浏览器分列过一遍](https://tlgrpv-web.com)，Chrome 和 Edge 基本同路径，Safari 在「设置 → 网站 → 摄像头」，Firefox 在「设置 → 隐私与安全 → 权限」。

判据很干脆：无痕能出二维码、常规窗口不行，问题百分百在第一层，跟账号、跟网络都没关系。

## 第二层怎么验：让浏览器把报错码说出来

第一层排除完，该看报错码了。这一步最容易被跳过，信息量却最大：

- `ERR_NAME_NOT_RESOLVED`：域名没解析出来，DNS 的问题。
- `ERR_CONNECTION_TIMED_OUT`：连不上，端口被挡或线路不通。
- `ERR_CERT_DATE_INVALID` / `ERR_CERT_AUTHORITY_INVALID`：证书日期无效或签发者不被信任。前者九成是系统时间不对，后者常见于公司网络做了中间人解密。
- `ERR_SSL_PROTOCOL_ERROR` / `ERR_HTTP2_PROTOCOL_ERROR`：握手被中间设备改坏，代理或安全软件插手的典型症状。

时间最容易漏。证书校验对时间容忍度很低，系统时钟慢十几分钟就足以让握手失败。Windows 走「设置 → 时间和语言 → 日期和时间」，打开「自动设置时间」再点「立即同步」；Mac 走「系统设置 → 通用 → 日期与时间」，勾「自动设置日期和时间」。

代理要留意"两套并存"：系统级代理在「设置 → 网络和 Internet → 代理」，扩展级代理在扩展自己的设置里，两层一起接管就会互相打架。验证办法是只留一套、另一套彻底关掉，再刷新。

还有一个常见的自坑：扫码的同时切线路。会话建立过程中 IP 突变，服务端会判异常，页面就卡在"等待确认"。从点开页面到登录完成这几分钟，线路别动。

## 第三层怎么验：去手机端看那张会话列表

前两层都干净、页面还是登不上，才轮到账号。别在浏览器里折腾了，打开手机上的 Telegram：「设置 → 设备（Devices）」，那里列着所有活跃会话。

**会话数到上限。** 同一账号能同时保持的活跃会话有上限，账号类型不同额度也不同。满了以后新设备授权要么不弹确认、要么直接失败，网页版就停在扫码那一步。把不用的会话点掉，或直接「终止所有其他会话」，再回电脑重扫。

**两步验证密码卡住。** 开了两步验证的账号，扫码后还要输一遍自定义密码，输错没有明显提示，只是原地打转。忘记密码只能走绑定的恢复邮箱重置，重置本身有等待期，这几天登不上属于正常现象，不是浏览器坏了。

**尝试次数太多。** 反复扫码、反复要验证码会触发临时限制，继续试只会延长限制，放一晚上再看比现场死磕划算。

更快的判断办法：手机端自己发一条消息。手机端也转圈发不出去，那是账号或整体网络的问题，跟浏览器一点关系没有。这类情况的处理入口站上归在「高频问题」里，[对着症状看更快](https://tlgrpv-web.com)。

## 三个让我白忙的判断错误

**清得越狠越干净。** 范围选「时间不限」，代价是这台电脑所有网站一起掉登录，修好电报再把邮箱、后台重登一遍。范围大，收益并不会更好。

**无痕能开就是我电脑坏了。** 恰恰相反，无痕能开说明电脑没坏，只是常规窗口里某个扩展或某条 Cookie 在捣乱，方向对了，两分钟定位。

**报错页是网站的问题。** `ERR_CERT_DATE_INVALID` 跟站点无关，是这台机器的时间或中间设备的问题。把它归给网站，就会一直原地清缓存。

## 把这三次清缓存换成三分钟判断

再遇到转圈，我按这个节奏走：先开无痕对照（三十秒），出得来就关扩展；出不来就看有没有报错码，没报错码盯系统时间和代理；两样都正常，掏手机看会话列表。整套不超过三分钟，比清三次缓存快，也不会把别处的登录一起赔进去。

一句话记住分层：**有报错码往链路查，没报错码往扩展查，能扫码但停住往设备列表查**。转圈本质上是浏览器在说"我还没连上"，它没说谎，只是很多人拿清缓存去回答一个网络和会话的问题。清理动作没错，错在把它当成唯一答案——手里有顺序，就不用靠运气。
