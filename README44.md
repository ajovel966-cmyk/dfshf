# 设备列表里多出一台陌生手机：先别点终止，把 6 个字段读完再决定（附三档处理动作对照表）

上周三凌晨一点多，我睡不着，随手打开手机 Telegram 的设置，翻了翻「设备」那一页。最上面是我正在用的这台，往下第二条写着「Xiaomi 13」——不是我的手机。我这台是 iPhone，家里人也都是 iPhone，公司配的备用机是台红米但型号对不上。手指已经按在「终止」上了，硬是停住了半分钟：万一是三个月前借同事那台机器扫码留下的？

那一晚我把六条会话一条条翻完，又把浏览器侧的痕迹对了一遍。那台小米是我自己留下的——去年十一月在朋友的安卓机上扫过一次码，关掉标签页就走了，会话一直挂着。这件事让我把这一屏彻底捋了一遍：每行写的到底是什么、哪些字段能当证据、哪些纯属误导。

写这篇的时候，我对着 👉 [Telegram网页版中文指南](https://tlgrqo-web.com) 里扫码确认与设备核对那几节逐条比过界面，下面说的字段名和按钮位置都以网页版和手机端现版本为准。

## **一、"陌生设备"有三种来路，先分类再动手**

看到不认识的一行就想踢，是本能；忍住不踢，是经验。设备列表里的陌生条目，来路基本落在三类里：

**自己留下的。** 换手机没退旧机、借别人电脑登过一次、公司一体机、平板、家里那台常年开着的笔记本——这类占比最高，我这次遇到的就是。共同特征是：设备型号说得通（你确实用过那个牌子），登录时间对得上某次具体的事。

**共用同一套东西。** 两个人用同一个账号，或者两个人用同一个浏览器配置文件。第二种最容易骗人：同一台电脑、同一个 Chrome，只是换了 Windows 账户，网页版那行可能显示成另一台机器的样子，因为会话标识是浏览器给的，不是人给的。

**真被别人登了。** 特征不在设备名，而在时间——它在你确定没碰过电脑的时段出现在线记录；或者你刚拒绝过一次登录卡片，列表里却多了一行。

分类做完，动作才有方向。跳过分型直接点「终止」，最坏的结果是把自己的旧设备踢了，真正的会话还留在列表第二页。

## **二、六个字段逐个读：每行都是一份小档案**

网页版和手机端的设备列表排版不同，字段是同一套。下面这张表是我逐条对着界面写的，**判断顺序按它从上往下走**：

| 字段 | 界面上的样子 | 能证明什么 | 最容易误读的地方 |
| --- | --- | --- | --- |
| **设备名** | `iPhone 13`、`Xiaomi 13`、`Windows` 这类 | 对方用的是什么终端 | 网页版不报真实机型，只报操作系统，看见 `Windows` 别以为是某台具体电脑 |
| **客户端标识** | 同行的 `Telegram Web`、`Telegram Desktop`、`Telegram Android` | 走的哪条通道 | `Telegram Web` 只说明「浏览器里的一次会话」，同一个人能开出好几条 |
| **位置** | 城市名，或国家 + 城市 | 这次连接的出口在哪 | 公司出口、公共 WiFi、加速线路都会让位置飘到别的城市，它证明不了人在哪 |
| **最近在线** | 「最近在线 3 天前」「在线」 | 这条会话最后一次活动的时间 | 显示「在线」不代表有人正坐着用它，后台心跳也会刷新 |
| **当前会话标记** | 该行高亮，或标着「当前设备」 | 你现在正从这条会话里看列表 | 它只标一条；网页版开两个标签页，另一条不会被标 |
| **会话年龄小字** | 部分版本在位置后面跟一句「已登录 42 天」 | 这条会话挂了多久 | 版本差异大：WebA（`web.telegram.org/a`）显示得细，WebK（`/k`）常常只给最近在线，别拿它当唯一判据 |

表的读法有个总纲：**设备名和客户端告诉你是谁，位置和最近在线告诉你是何时何地，会话年龄告诉你挂了多久。**前两个字段能造假的空间小，后三个字段的噪声大。很多人反过来看——先盯位置，一看「深圳」跟自己所在的杭州对不上，立刻判定被盗，这属于被自己的网络出口骗了。

反面例子：去年在一台装了公司 VPN 的笔记本上登录，那行位置显示香港，我照着这个「不对」翻了两天日志，结论是这台机器自己走的海底光缆出口。

## **三、三组时间一对，真假就出来了**

字段是静态的，时间是动态的。把列表里的时间和你的记忆对一遍，比看机型有用得多：

1. **最近在线对你的作息。** 那台设备的在线时段，有没有落在我睡觉、开会、飞机上的时间？落在里面，才值得警惕。
2. **登录时间对某件具体的事。** 我能不能说出「那天我在朋友家借他手机扫的码」这句完整的话。说不出来，就是红灯。
3. **位置对你当天的行程。** 位置对不上但时间对得上，先查网络出口；两样都对不上，再按最坏情况办。

我那台小米三条全对得上：时间是我在朋友家打游戏那晚，位置是他家那片，最近在线停在我关标签页的那一刻。所以它属于第一类，处理动作是留还是踢，取决于我的洁癖程度，不是安全问题。

## **四、处理动作分三档，按证据强度升级**

**第一档：确认是自己留下的——留着，但补一个动作。**网页版会话不占额外名额，留着不影响使用；补的动作是把这台的用途记在脑子里，别等到下次翻列表再猜一遍。

**第二档：来路说不清——直接终止。**手机端「设置 → 设备」，点那一行进去，底部有「终止会话」；网页版左侧菜单进「设置 → 设备」，每行右侧是终止按钮。点完那台设备立刻掉线，它下次刷新页面会看到「您的会话已失效，请重新登录」，控制台那条错误就是 `SESSION_REVOKED`。

**第三档：确认被登过——按这个顺序走，别跳步。**

1. 在手机端「设置 → 设备」里，把那台不认识的**单独终止**，不要一上来就点右上角「终止所有其他会话」。
2. 退回列表看一遍，确认那行**消失**了，而不是变成灰色或者还在等刷新。
3. 进「设置 → 隐私和安全 → 两步验证」，设一个密码，顺手填恢复邮箱——界面会提示忘记密码就无法登录，这句提示是真的，密码记在靠谱的地方。
4. 同一页往下，把「活跃会话」再翻一遍，看有没有第二条 `Telegram Web`。有两条，说明对方开过不止一个标签页。
5. 回到出事那台电脑，清浏览器侧的东西：Chrome 地址栏输入 `chrome://settings/content/all`，搜 `web.telegram.org`，把该站点的数据删掉；Edge 走 `edge://settings/siteData`，或者在「设置 → Cookie 和网站权限 → 所有站点」里找。清缓存不清站点数据，凭证还在，这一步最常被漏。
6. 隔一天再看一页。新增条目出现在你确定没登录过的时段，说明还有入口没堵住，这时候该动的是密码，不是设备。

第五步的细节在于：Cookie 里装的是会话凭证本身，[Cookie 与登录状态说明](https://tlgrqo-web.com) 这一节讲得比我细。清缓存只是把图片脚本扔掉，站点数据才是清凭证——两个按钮在两处，别点错。

## **五、踢完要验证，别只看按钮变灰**

动作做完了不等于生效了。我的验证方式固定三条：被踢那台浏览器刷新后回到二维码界面（不是停在半截的对话框上）；列表里那一行消失（不是变灰）；用那个浏览器重开一次，看到的是扫码界面，才算真干净。若它刷新后还能进聊天框，只是掉了一下又回来，说明你踢的是另一个标签页的会话。

## **六、下次扫码之前，先想清楚这台机器会留下什么**

设备列表这一屏，本质不是安全设置，是一本账。谁在什么时间、从哪个出口、用哪条通道进过你的账号，全在上面。它唯一管不了的是「你自己忘了」——我这次遇到的那台小米，不是入侵者，是我自己的记性。

所以流程反过来更好用：扫码前先问一句，这台机器用完我会不会回来退；扫码后第一件事不是回消息，是把 [扫码到设备核对的完整流程](https://tlgrqo-web.com) 里那一步照做——看一眼列表第一行是不是「当前设备」。借来的机器，走之前把标签页退干净、把站点数据清掉；自己的机器，隔一个月翻一眼列表，比出事之后翻日志省事得多。

那台小米我最后踢了。踢完给朋友发了条消息，让他以后别把浏览器借我——不是他的问题，是我这种「关掉标签页就算退出」的习惯，早晚要在别人机器上栽一次。
