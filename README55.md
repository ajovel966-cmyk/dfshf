## 这三个词根本不在一个维度上

大部分人把"独立IP""住宅IP""机房IP"当成三个并列选项，其实它们答的是三个不同的问题。

**独立 IP 讲的是分配关系**：这个出口是你一个人在用，还是几十个人共用。它跟这个 IP 属于谁、放在哪个机房毫无关系——一台云服务器只划给你一个人，那也是独立 IP。

**住宅 IP 讲的是归属**：这个地址由运营商分配给家庭宽带。你去看它的 ASN，名字长得像 Comcast、Deutsche Telekom、HKT、中国电信。对 Telegram 来说，那背后是一台真实用户的路由器。

**机房 IP 讲的是另一个归属**：地址段由 IDC 或云厂商持有，ASN 名字里带 Cloud、Hosting、Datacenter、Server、LLC。

**机场压根不是 IP 类型，它是一种卖法**：一条订阅给你一堆节点，每个节点是一个落地出口，通常几十上百人共用。所以机场的节点可能是住宅 IP，也可能是机房 IP，市面上九成是后者。

三件事可以任意交叉。最便宜的组合是"机场 + 机房 IP + 多人共用"，最贵的组合是"自建 + 住宅 IP + 独占"。

## 一张对照表，把三类出口摊平看

| 看什么 | 住宅 IP（原生家宽） | 机房 IP（IDC / 云） | 机场共享节点 |
| --- | --- | --- | --- |
| ASN 长什么样 | Telecom / Broadband / Cable / Mobile | Cloud / Hosting / Datacenter / Server | 看落地，多数落在第二列 |
| 一个出口背后几个人 | 一个家庭 | 1 到几十 | 几十到上百 |
| `/24` 里的邻居 | 真人家宽，TG 号密度低 | 常常整段堆满 | 整段被同一批用户轮流用 |
| 首次登录表现 | 最顺，很少弹二次验证 | 常见 `Too many attempts` | 取决于你那晚线路上有多少人 |
| 批量挪号 | 八个号分八条住宅线，稳 | 一条线灌八个，一串倒 | 最怕整批一起挪 |
| 单位成本 | 高，按 IP 按流量算 | 低 | 极低，几十块一堆节点 |

看表能看出我那次翻车的机理：延迟从 180ms 降到 38ms，代价是出口从一条冷清的住宅段换到了一条被反复灌过的机房段，而我又把八个号一次性塞进同一个 `/24`。号是干净的，环境是我自己弄脏的。

## 3 分钟自查：五个动作，测出你手上这条线是什么货

这套动作我现在每次换线路都跑一遍，从查 IP 到看 TG 的反应，三分钟能出结论。

1. **先让出口只剩一条线。** 关掉分流规则，Clash 里切"全局"，或者只保留一个节点。分流模式下你查到的只是"某一次请求走的那条"，不是 Telegram 真正走的那条，白测。
2. **查 IP 和 ASN 名字。** 跑 `curl -s https://ipinfo.io/json`，看 `ip`、`org`、`country` 三个字段。`org` 的值形如 `AS7922 Comcast Cable Communications, LLC`，AS 后面那串就是判据，看到 Hosting、Cloud、Datacenter 直接归类机房。
3. **用 Team Cymru 复核，顺便看段有多大。** 命令是 `whois -h whois.cymru.com " -v 1.2.3.4"`，返回一行竖线分隔的字段：AS | IP | BGP Prefix | CC | Registry | Allocated | AS Name。重点看 `BGP Prefix`——机场常见一整段 `/24` 全挂在同一个 ASN 下；再看换两三次节点，这个前缀变不变，不变说明你换的只是门牌号，还是同一条街。
4. **查这个 IP 有没有被标成代理。** 第三方 IP 信誉库会给 `usage type`（ISP / Hosting / Business）和 proxy 标记。一个被标了 proxy 的住宅 IP，等于花钱买了个机房。
5. **看 Telegram 自己的反应。** 登录时反复弹 `Too many attempts, please try again later`，或者刚进去就被要求补二次验证，再或者进 Settings → Devices（旧版叫 Active Sessions）发现登录地跟你选的节点国家对不上——三种都说明这条线路的出口跟你以为的不是一回事。

第 5 步最值得信。前四步查的是"这个 IP 客观是什么"，第五步查的是"平台实际把它当什么"，两者不一致时，以平台为准。

## 一个反常识：独立 IP 也可能很脏

一台机房 IP 只给你一个人用，手续上确实叫独立 IP。但它上个月可能还是某个批量注册脚本的出口，滥用记录挂在整个段上，谁接手谁继承。

Telegram 判断的不是"有没有人跟你抢带宽"，是"这个地址近期干过什么"。所以**独享和干净是两件事**，可以同时成立，也可以完全不成立。

反过来也成立：一条机场的住宅落地，如果你那个时段确实只有你在走，实际表现能压过一条被灌烂的独享机房 IP。

真正的判据得三个一起看：ASN 的出身（住宅还是机房）、同段的拥挤度（`/24` 里有多少活号）、这个 IP 近期的行为记录。缺一个都会判断错。

所以我看到 [TG小号批发](https://tlgroa-hao.com) 配置说明里那行"独立 IP 注册"时，只把它当成一个起点，不当成结论——它替你解决了注册端的分散度，没替你解决出口的洁净度。
