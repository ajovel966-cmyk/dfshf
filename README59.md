# 录了五条语音一条都发不出去：Firefox 上 Telegram 网页版麦克风权限四层表与 Opus 录音参数对照（含蓝牙耳麦、独占模式和 60 秒边界实测）

昨天晚上给同事补一段口述版的修改意见，我在 Firefox 里按住麦克风，同一句话说了五遍。第一遍松手后波形是平的，一毫米都没跳；第二遍有波形，但时长死死停在 0:00；第三遍时长正常、点发送后转圈十几秒，跳出一个红色感叹号；第四遍我换成蓝牙耳麦，发出去的声音闷得像从水缸里传出来；第五遍干脆连授权弹窗都不出现了，按住只有一圈灰色的环。

五条语音，四种死法，全都长着"发不出去"这张脸。但把权限链和录音参数逐条对下来会发现，它们卡在完全不同的两层上：前三种在本地麦克风这条线上，最后一种在上传那条线上。混着修，只会把能用的那层也拆坏。下面的对照表是我那天按顺序试出来的，同类步骤在 [纸飞机网页版中文的权限说明](https://tlgrgs-web.com) 里也有图文版可核。

## **一、先分清是"录不进去"还是"发不出去"**

网页版发语音是两段拼起来的：本地录（麦克风 → 编码器 → 一段音频数据）和往外发（音频数据 → 上传 → 落到对话里）。两段出问题长得极像，判别只看三个地方。

- **波形**：按住说话时有起伏，说明麦克风数据已经进来了，权限这层基本是通的。
- **时长**：松手后显示 0:03 这种真实秒数，说明编码器吃到了数据；一直显示 0:00 或者干脆不显示，是数据流是空的。
- **失败形态**：红色感叹号 + "重试"，或者一个小云朵图标不动，这属于上传；按住毫无反应、连弹窗都没有，属于权限；按住后弹一句"无法访问麦克风"，多半是设备被别的程序攥着。

我那条"有波形但 0:00"的语音，最后查明是麦克风被会议软件占了半边，Firefox 拿到了设备句柄，却收不到任何采样——波形是界面自己画的占位动效，不是真声音。

## **二、麦克风权限的四层，缺一层就哑**

Firefox 在 Windows 上的麦克风是一条四段串联的链，任何一段关着，表现都可能是"点了没反应"。这张表按从内到外的顺序排：

| 层级 | 具体位置 | 被拦住时的表现 | 要改成什么 |
| --- | --- | --- | --- |
| **① 站点权限** | 地址栏锁图标 → 更多信息 → 权限 → 使用麦克风 | 按住麦克风无任何反馈，无弹窗 | 取消"使用默认值"，选"允许"；或点"清除权限"让它重新问 |
| **② Firefox 全局名单** | 地址栏输 `about:preferences#privacy` → 滚到"权限" → 麦克风 → 右侧"设置…" | 弹窗一闪而过或永不出现，换了标签页也一样 | 在列表里搜到该域名后删掉——这里只有允许/阻止两态，删掉才回到"询问" |
| **③ Windows 应用授权** | 设置 → 隐私和安全性 → 麦克风 → "让桌面应用访问你的麦克风" | 浏览器里怎么点都不弹窗，其它软件也录不到 | 总开关和下面 Firefox 那一项都要打开 |
| **④ 设备独占/占用** | `mmsys.cpl` → 录制 → 麦克风 → 属性 → 高级 → 独占模式 | 弹窗正常、授权成功，但录音 0:00 或报 `NotReadableError` | 取消"允许应用程序独占控制该设备"；顺手关掉正在后台录音的软件 |

第①层最坑的一点是**它有记忆**。第一次不小心点了"不允许"，Firefox 会把这条决定记在站点上，之后再不弹窗，你只会觉得功能坏了。第③层常被漏掉，因为它是系统级的：Windows 把"桌面应用"（Firefox 属于这一类）和商店应用分成两个开关，只开其中一个，浏览器照样拿不到设备。

第②层还有个版本差异值得记一下：近两年的 Firefox 在隐私设置里把麦克风、摄像头、通知合成了一块"权限"区，老版本则分散在"隐私与安全"下面两处；找不到"设置…"按钮时，先在设置页顶部的搜索框里打"麦克风"，能直接跳到对应区块。

## **三、录音参数：网页版到底录出了什么**

录进去之后还有一层容易被忽略的东西——编码参数。网页端的语音走浏览器的 `MediaRecorder`，落到 Opus 编码、单声道、48 kHz 采样、24–32 kbps 这一段区间，容器是 Ogg 还是 WebM 取决于浏览器实现，服务端会统一转码。这个量级意味着一分钟语音大概只有两三百 KB，所以"文件太大发不出去"这条在语音消息上几乎不成立——真发不出去，问题在上传通道，不在体积。

参数层面真正会造成故障的是这三处：

**采样率对不上。** 蓝牙耳麦一旦切到"免手操作"（Hands-Free）模式，麦克风只剩 8 kHz 或 16 kHz 单声道，录音照样成功，声音却又闷又破，同事听到的就是我第四遍那种水缸音。要清晰就得让它走 A2DP，但 A2DP 在多数机器上是纯播放通道，当麦克风用时会被系统自动踢回 HFP——这是蓝牙链路本身的限制，不是浏览器能改的。

**降噪和音频增强。** Windows 的"麦克风增强""噪音抑制"开着时，说话开头那一两个字的音量常被当成底噪吞掉，录出来是一段静音开头。设备属性 → 级别 里把增强项关掉，比换麦克风有用。

**时长边界。** 语音消息有录制上限，手机端是 60 秒；超了之后界面会自动切成"以音频文件发送"，走的是文件上传通道，权限没问题也可能失败。我撞到过一次：按住说了七十多秒，松手后转成一个小文件图标，然后一直转圈——那不是麦克风坏了，是附件上传被拦。

## **四、一次配通的六步**

按这个顺序走，基本不会绕圈：

1. 先关掉所有可能占着麦克风的程序：会议软件、录屏工具、语音输入法、另一标签页里的语音聊天。
2. 地址栏锁图标 → 更多信息 → 权限 → 使用麦克风，改成"允许"，然后 `Ctrl + R` 刷新页面。权限改动不热生效，不刷新等于没改。
3. `about:preferences#privacy` → 权限 → 麦克风 → 设置…，确认这个域名不在阻止名单里。
4. Windows 设置 → 隐私和安全性 → 麦克风，总开关和 Firefox 那一项都打开。
5. `mmsys.cpl` → 录制 → 选中正在用的麦克风 → 属性 → 高级，取消独占模式。
6. 回页面按住说三秒，重点看松手后的时长是不是真实秒数，而不是 0:00。

这六步里只有第 2 步会立刻见效，其余都是排他性检查——所以我建议一次全过一遍，别一条条试，试一条刷一次页面，时间全耗在等加载上。

## **五、录音正常但发不出去，看这三处**

时长正常、波形正常、点了发送却没落地，麦克风这条线就是干净的，别再动权限设置。剩下三种可能：

**标签页挂太久，会话过期。** 网页版开着过夜，界面还在，长连接已经断了，新消息连红叹号都不给，就静静躺着。刷新一次页面，草稿一般还在输入框里，重按发送就行。

**网络在中途换了出口。** 语音上传是个持续几秒的连接，中途切节点或断一次 Wi-Fi，就会停在半路。表现是那个小云朵图标一直不动。等网络稳定后长按消息选重发。

**容器标签或无痕窗口的权限是临时的。** 用容器标签分工作号和私人号时，每个容器都算一个新站点，第一次用要重新授权；无痕窗口关掉就清空，下次继续问。不少人以为是"权限又坏了"，其实只是它按设计在重新问一遍。

## **六、下一次按住麦克风之前**

那五条语音我一条都没重录。前三条靠第 2 步和第 5 步解决——权限被记成了"阻止"，加上独占模式被别的软件占着；第四条我干脆换回有线耳麦，蓝牙那套不折腾了；第五条是把七十多秒的内容拆成两段，各自都在上限内。

Firefox 在媒体权限上的脾气是"记得住、不提醒"：你点过一次不允许，它就默默执行到底，界面上一点提示都不给。所以语音发不出去时，别急着重装浏览器或换客户端，先把锁图标点开看一眼那条麦克风状态——十次里有六七次，问题就摆在那行字里。要连着其它排障场景一起看，站点上的 [浏览器媒体权限与通知排查](https://tlgrgs-web.com) 那一节把麦克风、摄像头、通知三条线分开写了，对着自己卡住的那一步查更省事；语音之外的收发问题，也可以从 [纸飞机网页版中文](https://tlgrgs-web.com) 的目录按现象往下找。

按住麦克风之前花三十秒过一遍上面那张四层表，比事后录五遍管用。
