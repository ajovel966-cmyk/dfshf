# 远程重启后再也连不上？向日葵无人值守与开机自启的 9 项配置清单（Windows、macOS、Linux 逐项对照）

上周四凌晨一点半，我给一台异地托管的 Windows 机器打补丁。远程窗口里敲完 `shutdown /r /t 0`，屏幕一黑，我以为五分钟就能回来。结果向日葵的设备列表里，那台机器从“在线”翻成灰色，之后二十分钟再没亮过。机房在另一座城市，值班的人第二天九点才到，我只能对着一个连不上的设备码干等。第二天查到原因时我有点想笑：机器好好开着，系统也正常，只是被控端根本没跟着系统一起起来——「开机自动启动」这个开关，从装机那天起就没人碰过。

这件事之后我把“无人值守”拆成了一张清单，一台一台对着改。写在这里，给同样要跨城管机器的人。

## 无人值守不是一个开关，是一串必要条件

多数人对无人值守的理解停在“设个固定密码”。密码只是入场券，它解决的是“进去的时候不用找人点同意”。真正决定你重启后还能不能连上的，是另外三件事：被控端有没有在系统启动时自动跑起来、它跑起来的位置对不对（登录前还是登录后）、以及供电和网络有没有把机器留在“可连”的状态。

这三件事任意一件断掉，你在外面看到的现象都一样：设备离线。所以这类问题不能从“连不上”倒着猜，要顺着“重启那一刻它经历了什么”往下看。

下表是我按九个必要项整理的，Windows 是主战场，后两栏是实际用下来最容易出事的地方。

| # | 配置项 | Windows 里的位置 | macOS / Linux 对应 | 漏配之后会发生什么 |
| --- | --- | --- | --- | --- |
| 1 | 允许被控 | 主界面顶部「允许被控」开关 | 客户端「设置」里的被控开关 | 连得上但立刻被拒，提示对方不允许被控 |
| 2 | 开机自动启动 | 齿轮「设置」→「常规」→「开机自动启动」 | 登录项 / systemd 服务 | 重启后设备一直灰着 |
| 3 | 以系统服务方式运行 | 「设置」→「常规」，部分版本在「安全」下 | launchd / `systemctl enable` | 停在登录界面时连不进去 |
| 4 | 固定验证码 | 「设置」→「安全」→「本机验证码」 | 同名设置项 | 临时码每次重启都变，等于没有密码 |
| 5 | 快速启动 | 控制面板「电源选项」→「选择电源按钮的功能」 | 无此概念 | 网卡和服务带着休眠状态醒来，连不上 |
| 6 | 断电恢复自动上电 | BIOS 的 Restore on AC Power Loss | 同 BIOS | 停电或误拔电后机器就一直关着 |
| 7 | 锁屏与登录密码 | 系统账户必须有密码 | 同 | 连进去卡在登录框，动不了 |
| 8 | 屏幕录制/辅助功能授权 | 不涉及 | 系统设置「隐私与安全性」 | 能看不能操作，或直接黑屏 |
| 9 | 安全软件白名单 | 防火墙、EDR 放行出站 | 防火墙 | 卡在「正在连接」然后超时 |

## Windows：六步把机器配成“重启也能自己回来”

1. **先确认允许被控**。主界面顶部把「允许被控」打开，这是最基础的一条，装完默认是开着的，但有人为了安全手动关过，之后就忘了。
2. **打开开机自启**。右上角齿轮进「设置」→「常规」，勾上「开机自动启动」。这一项只保证“有用户登录进桌面之后启动”，它管不了登录界面之前的阶段，所以别停在这一步。
3. **改成服务方式运行**。同一页找到「以系统服务方式运行」（有的版本写在「安全」分类下），勾上并重启一次。验证办法很简单：`services.msc` 里能看到对应的向日葵服务，启动类型是「自动」。这一步是整张清单里最关键的一项。
4. **设固定验证码**。「设置」→「安全」→「本机验证码」，改成自己记的固定密码。识别码是门牌号，不随 IP 变；验证码是门禁口令，没固定的就等于每次重启换一把锁。
5. **关掉快速启动**。控制面板 →「电源选项」→「选择电源按钮的功能」→「更改当前不可用的设置」，取消「启用快速启动」。省下的那几秒，代价是网卡和服务带着上次休眠的残影醒来。
6. **进 BIOS 设上电策略**。找到 `Restore on AC Power Loss` 或 `AC Power Recovery`，值从 `Power Off` 改成 `Power On`。机房跳闸一年总会碰上一回，这一项决定了你是远程开工还是派人跑现场。

配完之后还有一处容易误判：重启后停在 Windows 登录界面是**正常**的。以服务方式运行的被控端此时仍然能接受连接，只是连进去先看到系统的登录框，要再输一次系统账户密码——所以那台机器必须设密码，空密码账户在这里是进不去的。

## macOS 与 Linux：权限会掉，服务要手动 enable

macOS 的坑集中在两个地方。一是「系统设置 → 通用 → 登录项」里要把向日葵加进去，只在客户端里勾「开机自启」不够，重启后它不会自己出现。二是「隐私与安全性」里的「屏幕录制」和「辅助功能」——大版本升级之后这两项授权会被系统重置，表现是连接正常、桌面看得见，但鼠标键盘毫无反应，很多人以为是软件坏了，其实是权限掉了。顺手把「锁定屏幕」里的自动休眠设成「永不」，机器睡了，设备码就是个死的编号。

Linux 看发行版和会话类型。装了桌面版的先用 `systemctl status sunloginclient` 看一眼服务，没生效就 `systemctl enable --now sunloginclient` 让它跟着启动。没有图形界面的服务器要留意会话类型：Wayland 下被控端经常只给出一片黑屏，切回 Xorg 会话登录才正常。安装包还分架构，[按系统下载对应版本](https://magnum-quest.com) 的时候别选错，x86 和 ARM 装反了连服务都起不来，报错也看不出是装错了包。

## 自己安排一次重启，比等故障找上门划算

配置完不要等真出事。挑一个能联系上现场的时间，做一次完整演练：

1. 从控制端连进去，确认画面和键鼠都正常；
2. 在远程窗口里**重启**被控端，别点“注销”——注销测不出服务有没有跟着系统启动；
3. 主动断开控制端，等三到五分钟；
4. 重新发起连接，看它是直接进桌面，还是停在 Windows 登录框。停在登录框也算成功，说明服务已经起来了；
5. 如果设备一直灰着，先别重装，按下一节的对照表查。

演练结果建议写下来：日期、重启方式、恢复耗时。一次真实的恢复耗时比十张配置截图都管用，交接的时候也省口舌。

## 连不上时按现象对照，别从重装开始

| 现象 | 最可能的原因 | 处理动作 |
| --- | --- | --- |
| 列表里一直显示灰色的「对方已离线」 | 被控端没随系统启动，或机器根本没上电 | 现场确认供电与 BIOS 上电策略，远程救不回来 |
| 连上后停在 Windows 登录界面 | 服务已启动，但系统还没人登录 | 正常现象，输入系统账户密码继续 |
| 提示「验证码错误，请重新输入」 | 用的还是临时验证码，重启后已经变了 | 改成固定密码，或让现场读当前验证码 |
| 连上黑屏，或键鼠无响应 | macOS 授权被重置；Linux 跑在 Wayland 会话 | 重新勾选屏幕录制与辅助功能；切 Xorg |
| 卡在「正在连接」直到超时 | 出口网络被拦，或安全软件把它当可疑行为 | 换网络验证一次，把客户端加进白名单 |

## 密码、屏幕，和“该不该一直开着”

无人值守本质上是把一台机器的门长期虚掩着。固定密码别用生日和工位号，单独起一串只在远程用的；机器摆在开放办公区或门店收银台的，连进去先开隐私屏，屏幕上只留一句“维护中”。企业侧还能看连接日志和设备分组，定期翻一遍有没有非工作时间的登录。[站上的分平台图文步骤](https://magnum-quest.com) 把权限项和排查顺序分开列了，可以对着自己那台机器逐条勾。
